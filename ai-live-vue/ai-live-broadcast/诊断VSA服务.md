# VSA 服务启动超时问题 - 诊断指南(打包版)

## 问题描述

每当进入软件进行语音开播时,可能出现以下错误:
```
[App] 语音服务自动启动失败: VSA 服务启动超时
```

## 使用内置诊断工具(推荐)

### 适用于打包后的Windows程序

已经为您创建了内置诊断功能,无需命令行操作,直接在应用内使用:

#### 使用步骤

1. 打开应用,点击"AI服务器设置"
2. 确保选择"本地语音服务"
3. 找到"服务诊断"部分
4. 点击"诊断VSA服务"按钮
5. 等待诊断完成(约30-60秒)

#### 诊断内容

诊断工具会自动检查:
- ✓ VSA 文件完整性 (vsa.exe, app.py, 模型目录等)
- ✓ 端口 23456 占用情况
- ✓ VSA 服务运行状态
- ✓ 尝试启动 VSA 并记录启动耗时

#### 查看结果

诊断完成后会在界面上显示:
- **诊断摘要**: 成功/警告/错误数量
- **发现的问题**: 列出所有错误和警告
- **解决建议**: 根据问题类型提供具体的解决方案
- **诊断报告**: 点击"查看报告"可以打开详细的JSON报告文件

## 问题原因分析

根据代码分析,该错误在以下情况下出现:

1. **启动流程**:
   - App.vue 在应用启动时自动检查配置
   - 如果选择本地语音服务,会调用 `start-voice-service` IPC
   - voiceServiceManager 启动 VSA 服务后等待最多30秒
   - 通过 HTTP 轮询检查 `http://127.0.0.1:23456` 是否响应

2. **可能的原因**:
   - VSA 服务启动耗时超过30秒 (模型加载慢、机器性能不足)
   - 端口 23456 已被占用
   - VSA 进程启动失败但未立即报错
   - Python环境或依赖问题

## 根据诊断结果的解决方案

### 1. 端口被占用

**症状**: 诊断报告显示"端口 23456 已被占用"

**解决方法**:
1. 打开任务管理器(Ctrl+Shift+Esc)
2. 找到占用端口23456的进程(可能是之前未关闭的VSA进程)
3. 结束该进程
4. 重新启动应用

**命令行方法**:
```bash
# 查看占用进程
netstat -ano | findstr :23456

# 终止进程(PID是上面命令查到的进程ID)
taskkill /F /PID <PID>
```

### 2. VSA 文件不完整

**症状**: 诊断报告显示"VSA 目录不存在"或"app.py 不存在"

**解决方法**:
1. 确认以下文件/目录存在:
   - `应用目录/extra/vsa/app.py` (必需)
   - `应用目录/extra/vsa/vsa.exe` (Windows推荐)
   - `应用目录/extra/vsa/data/models/` (至少包含一个有效的模型目录)
2. 如果文件不完整,重新解压 `vsa.rar` 到 `extra/vsa/` 目录
3. 确保解压后的目录结构正确

### 3. 启动时间超过30秒(最常见)

**症状**: 诊断报告显示"VSA 服务启动失败，耗时 30.XX 秒"

**原因**:
- 电脑性能不足(显存不足、CPU负载高)
- 模型文件较大,加载需要更多时间
- 后台程序占用显存

**解决方法A - 增加超时时间**(推荐):

打开开发者工具(F12),在控制台执行以下操作:
1. 打开应用安装目录
2. 找到并编辑文件: `resources/app/dist/electron/main.js`
3. 搜索 `waitForService('vsa', 30)`
4. 将 `30` 改为 `60` (增加到60秒)
5. 保存并重启应用

**解决方法B - 优化启动环境**:
1. 关闭其他占用显存的程序(游戏、视频编辑软件等)
2. 确保至少有8GB可用显存
3. 不要在VSA服务启动时进行其他高负载操作

**解决方法C - 手动预启动**:
1. 在打开应用之前,先手动启动VSA:
   ```
   双击: 应用目录/extra/vsa/vsa.exe
   ```
2. 等待VSA完全启动(看到命令行窗口显示 "Running on http://127.0.0.1:23456")
3. 然后再打开应用

### 4. Python 环境问题

**症状**: 诊断报告显示"Python 环境不存在"或启动日志中有Python错误

**解决方法**:
- Windows环境: 确保使用 vsa.exe (已打包所有依赖)
- 如果vsa.exe不存在,确认 `extra/vsa/py310/python.exe` 存在
- 检查Python依赖是否完整

## 临时解决方案

### 方案1: 禁用自动启动

如果您希望手动控制VSA服务启动时间:

1. 打开"AI服务器设置"
2. 切换到"云端AI服务器"(临时)
3. 保存设置
4. 关闭应用
5. 手动启动 `extra/vsa/vsa.exe`
6. 等待服务完全启动
7. 重新打开应用
8. 切换回"本地语音服务"

### 方案2: 查看详细日志

如果需要查看更详细的启动日志:

1. 打开"AI服务器设置"
2. 启用"调试模式"
3. 保存设置并重启应用
4. VSA服务窗口将可见,可以看到实时日志输出

## 技术支持

如果以上方案都无法解决问题:

1. 运行诊断工具
2. 点击"查看报告"按钮
3. 将 `vsa-diagnostic-report.json` 文件发送给技术支持
4. 报告中包含完整的诊断信息,有助于快速定位问题
